## D2 · Git 工作流 + 双系统同步规范

2.5h · 目标：两个系统靠 push/pull 同步，不出冲突

**必做的四项全局配置（Windows 和 Linux 各配一遍）**：

```bash
git config --global core.quotepath false     # 中文文件名正常显示
git config --global core.autocrlf false      # 不改换行符，双系统必需
git config --global core.filemode false      # 忽略权限位变化
git config --global init.defaultBranch main
```

**双系统铁律**：

- ❌ 绝对不要把仓库放在 NTFS 分区上让两个系统共用 —— 权限位和换行符都会出问题
- ✅ 两个系统**各放一份 clone**，靠 push / pull 同步
- 换系统前必做：`git push`；进另一个系统第一件事：`git pull`
- 口诀：**开工先 pull，收工必 push**
- push 被拒时用 `git pull --rebase`，**永远不要用 `git push -f`**

**验收**：两个系统都能 push / pull / commit message 规范

## D4 · C 内功：位操作三件套 + volatile

5h 攻坚日 · 目标：位操作刻进肌肉记忆

STM32 编程 90% 的时间在跟寄存器打交道，全靠位运算。**面试第一关必考。**

```c
x |=  (1U << n);        /* 置位：第 n 位设 1 */
x &= ~(1U << n);        /* 清零：第 n 位设 0 */
(x >> n) & 1U;          /* 取位：读第 n 位 */

(x >> 4) & 0x0FU;       /* 取第 4~7 位 */
x &= ~(0xFU << 4);      /* 第 4~7 位清零 */
```

- **为什么用 `1U` 而不是 `1`**：无符号数移位行为明确，避免符号位扩展。面试常追问。
- **`volatile` 为什么必须有**：告诉编译器「这个变量可能被硬件或中断改，别优化掉」。不加的话，指针指向寄存器的代码在 `-O2` 下会被优化成死循环 —— 嵌入式最经典的坑之一。

**动手**（必须自己写）：

1. 做 `week02/c-internals/exercises.c` 的 **ex1 / ex2 / ex3**
2. 再写三个自己的版本：第 0 位和最高位同时置 1 / 一个字节高低位交换 / 不用 if 判断两数大小
3. `gcc -Wall -Wextra` 编译，**必须零警告**

**验收**：三个操作能默写 / 能解释为什么用 `1U` / 能解释不加 volatile 的后果 / ex1~ex3 通过

## D7 · 大小端 + 结构体对齐

2h · 目标：能算、能解释、能踩坑

**大小端**：小端 = 低字节存低地址（x86、STM32 都是小端）

```c
/* 联合体法 */
union { uint32_t i; uint8_t c[4]; } u; u.i = 1; return u.c[0] == 1;
/* 指针法 */
uint32_t x = 1; return *(uint8_t*)&x == 1;
```

为什么重要：串口/网络传数据时，**对方大端你小端，数据全错** —— 通信协议最高频的 bug。

**结构体对齐两条规则**：

1. 每个成员的起始地址，必须是**自身大小的整数倍**
2. 结构体总大小，必须是**最大成员大小的整数倍**（末尾可能补字节）

`#pragma pack(1)` 强制 1 字节对齐，用在**通信协议结构体**上，但会牺牲访问速度。
⚠️ 用完**必须 `#pragma pack()` 恢复**，否则后面所有结构体都是 1 字节对齐，会引发极难定位的 bug。

**动手**：

1. 做 **ex4（大小端）、S6 / S7（结构体对齐、pack 对比）**
2. 自己设计一个通信帧结构体（帧头 1B + 长度 2B + 数据 NB + 校验 1B），分别算默认对齐和 `#pragma pack(1)` 下的 sizeof

**验收**：两种方法判断大小端 / 能说出 STM32 是小端 / 能手算 sizeof 并验证 / ex4、S6、S7 通过
