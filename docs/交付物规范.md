# 交付物规范

本仓库的每个学习节点都必须产出**可被他人检验**的东西。规则如下。

## 一、四类交付物

| 类型 | 最低要求 | 存放位置 |
|---|---|---|
| 代码 | 能编译通过、能运行、关键行有注释 | `weekNN/` 对应目录 |
| 视频 | 1~8 分钟，必须有口播讲解 | 网盘 / B 站，链接写进 `videos/README.md` |
| 笔记 | Markdown，含知识点、验证方法、「我踩的坑」 | `notes/` |
| 截图/图 | 能证明某件事成功了的图 | `docs/img/` |

**硬规则**：四类缺一不可。没有视频节点的那天，也必须有代码 + 笔记。

## 二、命名规范

```
notes/     w01-d04-寄存器点灯.md          # w<周>-d<天>-<主题>
docs/img/  w01-d04-gpio-register.png      # 与笔记同名
videos/    w01-d04-register-explain.md    # 链接文件条目
week01/    d04_led_register/              # 天号 + 下划线 + 描述
week02/    c-internals/pointer_array.c    # 按主题分目录
```

**笔记标题格式**（每篇必含）：

```markdown
# 主题名称

- 日期：2026-XX-XX
- 投入：X 小时
- 对应阶段：D4 / 阶段 2 外设

## 一、今天搞懂的事
（用自己的话写，不要复制教程）

## 二、动手验证
（跑了什么代码、看到什么现象、截图路径）

## 三、我踩的坑
（现象 → 排查过程 → 根因 → 解决）   ← 这部分最重要，面试就靠它

## 四、还没搞懂的问题
（留着，下一个缓冲日专门解决）

## 五、面试可能怎么问
（把这周的内容翻译成 2~3 个面试问题，并写上 3 句话的答案）
```

## 三、视频要求

三类视频，作用不同：

### 1. 演示型（≤1 分钟）
只证明「它真的跑起来了」。
- 画面必须能看到硬件动作（LED 闪、屏幕显示、波形）
- 口播一句现象说明，例如「这是 PC13 推挽输出，500ms 翻转一次」

### 2. 讲解型（3~8 分钟）★ 最重要
**假装在给面试官讲。** 这是整个机制里最有价值的部分 —— 讲不顺的地方，就是你还没真懂的地方。
- 必须对着代码或纸笔讲，不能只念代码
- 必须回答指定的几个问题（见每天的交付物说明）
- 要求全程不卡壳。卡了就重录，或者停下来搞清楚再录

### 3. 周总结型（约 3 分钟）
- **不写稿，对着镜头直接说**：本周学了什么、哪里卡住了、怎么解决的、下周注意什么
- 这个练习直接对应面试的自我介绍和项目讲述

**存放方式**：视频文件不进 Git（太大）。上传百度网盘 / 夸克网盘 / B 站（可设私密），把链接和一句话简介写进 `videos/README.md`。

## 四、Commit 规范

```
格式：<类型>(范围): <简短描述>

类型：feat / fix / docs / refactor / chore
```

✅ 正确：

```
feat(week01): 用寄存器方式点亮 PC13 LED
docs(notes): 补充 GPIO CRH 寄存器位定义
fix(week01): 修正 RCC_APB2ENR 的 IOPC 位掩码
chore(progress): 完成第 1 周打卡
```

❌ 禁止：`update` / `提交` / `asdf` / `123`

**为什么较真**：面试官打开 GitHub 第一眼看的就是 commit 历史。一条条清晰的记录比任何简历描述都有说服力 —— 它证明你是一步步做出来的，而不是最后一天批量提交的。

## 五、每个节点完成后的固定动作

1. 代码放进对应目录，`git add` → `git commit`（用规范信息）→ `git push`
2. 视频上传，链接写进 `videos/README.md`（记得一起提交）
3. 笔记写完，加进 `notes/README.md` 索引
4. 截图放进 `docs/img/`
5. 更新 `PROGRESS.md`，把 `[ ]` 改成 `[x]`
6. 最后再提交一次：`chore(progress): 完成 D<N>`

## 六、每周必须维护的两份长期资产

| 文件 | 内容 | 为什么 |
|---|---|---|
| `notes/寄存器速查表.md` | 每个外设用到的寄存器、位定义、地址偏移 | 面试前 10 分钟就能过一遍，平时也不用反复翻手册 |
| `notes/踩坑库.md` | 每个 bug 的现象 / 排查 / 根因 / 解决 | 面试问「遇到过什么难题」，这是你的弹药库，且比编的答案可信得多 |

这两份文件从第 1 周就要开始建，越往后越值钱。
